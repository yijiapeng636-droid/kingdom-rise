# 后续开发建议

先确认 MVP 能完整经历建造—生产—第 3 日袭击—领取战利品—继续经营，再考虑扩展。

## 第一阶段：稳定性和表现

- 连接真实 npm 环境运行 `npm install`、`npm run build`，在 Chromium 和移动屏幕尺寸下做交互验收。
- 使用 Tiled JSON + Atlas 素材替换占位绘制。为地形添加不可通行障碍、局部移动避让和导航缓存。
- UI 增加明确的作业状态、施工参与者、人口容量、伤员倒地倒计时、俘虏汇总。
- 扩充持续压力下的经济/战斗平衡测试，尤其确认仓库满、食物短缺、施工堵路、领袖死亡等边界。

## 第二阶段：更深的核心玩法

- 砍树/采矿运输、居民职责切换和资源链。
- 多种敌人/防御单位与城墙修理系统。
- 增加战斗行动（支援/救治/撤退）与单位站位、选择组。
- 收容容量、俘虏意愿/招募、对话与事件后果。

## 第三阶段：扩张

- 地形/营地存档版本迁移、多个场景模板、地图编辑器支持。
- 工坊/市场/商队、任务系统和科技解锁。
- 当真正需要跨设备或多人时，再设计后端 API、MySQL 和权限体系；不要让前端原型假装已有联网同步。
